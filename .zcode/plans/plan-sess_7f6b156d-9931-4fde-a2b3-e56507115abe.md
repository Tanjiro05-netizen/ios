## Goal

Bring the website's **text-edition reader** (the new fullscreen reader alongside the EPUB reader and PDF viewer, built in "Marxist-Platform copy 2/4") to the iOS app, so **all 59 communist-left.org text books** already ingested in Supabase become readable natively. No backend work is needed — the app and website share the same Supabase project (`yghsprwrzgfegvfbjmkq`), and the books live in `digital_library_books.text_edition` (JSONB: `{sections: [{id, title, level, md}], reading_minutes, source, generated_at}`), flagged `is_official = true`, no EPUB/PDF/covers.

Today those books open in the app to a dead description page because `Book` doesn't decode `text_edition` and there is no reader for it.

## Changes

**1. `Sources/Models.swift` — model + decoding**
- Add `TextEditionSection { id, title, level, md }` and `TextEdition { sections, readingMinutes, source, generatedAt }` (Codable/Hashable; snake-case decoder already handles `reading_minutes`/`generated_at`).
- Add `var textEdition: TextEdition? = nil` to `Book` (defaulted so existing memberwise-init call sites keep compiling).

**2. `Sources/API.swift` — queries**
- `LibraryClient.fetchBooks`: change `select=*` to an explicit column list **excluding `text_edition`** (lists would otherwise pull ~10 MB of markdown), and raise `limit` from 40 → 200 so the whole catalog (59 text editions + 17 EPUB titles + existing records) appears in the Library grid.
- `fetchBook(id:)` keeps `select=*` so the reader gets the full `text_edition`.

**3. New `Sources/TextEditionReaderScreen.swift` — the fullscreen reader (native SwiftUI, website parity)**
Structure mirrors the website's `TextEditionReader`/`BookReaderPage` precedence: **EPUB first, then text edition, then PDF/description** — implemented as a dispatch branch inside the existing `ReaderScreen` after its `fetchBook` (so Library taps, Continue Reading, search and deep links all work unchanged, exactly like `BookReaderPage.jsx` picks the surface).
- Fullscreen: navigation bar hidden, theme background edge-to-edge, safe-area-aware sticky top bar with back button.
- Sticky top bar: crimson progress rule along the top edge (scroll %), current chapter title, `NN / NN · X min` counter, A− / A+ font controls (persisted via existing `ios.reader.fontSize`).
- Whole book in one scrolling column (`ScrollView` + `LazyVStack` + `ScrollViewReader`) — the "document itself scrolls" behavior of the website; serif prose, headings sized by section `level` (level ≥ 3 smaller), first "Front matter" heading hidden, diamond section dividers (line + rotated crimson square + line).
- Sections rendered with the existing native markdown renderer `StudyMarkdownDocument` (headings, lists, quotes, tables, inline styles all supported).
- Scroll-spy via geometry preference keys → active section highlight + progress %; jump-to-section from a numbered TOC sheet styled like the website's chapter rail (crimson `01, 02…` numbers, indent for level > 1).
- Reading state: restore last section per book (`UserDefaults`), report progress through the existing `ReadingActivityStore.upsertProgress` (Continue Reading rail works out of the box), bookmark button saves the reading place / selected quote.
- Reuse `ReaderSettingsSheet` (night/sepia/paper themes + font slider); apply theme background with a matching `.colorScheme` override so native text colors stay legible.
- Empty-edition fallback keeps today's description/PDF-share path.

**4. `Sources/Screens.swift` — dispatch**
- In `ReaderScreen.body`: if `book.epubFilename == nil` and `textEdition.sections` is non-empty → show `TextEditionReaderScreen` instead of the EPUB webview + toolbar (`.toolbar(.hidden, for: .navigationBar)`).

**5. Tests (`Tests/MarxistForumTests.swift`)**
- Decode a sample `text_edition` JSON (snake_case keys) → verify sections/`readingMinutes`; decode a book without `text_edition` → nil.

**6. Build & verify**
- `xcodegen generate` (project.yml already globs `Sources/`, so the new file is picked up), then `xcodebuild` build + the app's test suite.
